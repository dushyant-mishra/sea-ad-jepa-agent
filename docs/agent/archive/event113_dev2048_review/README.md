# DEV2048 and JEPA scorer repair draft (no training)

The DEV2048 helpers are based on draft #597 `bfcba24ed3fcfbf146eaf7700c78ad1553fc6cee`, the original PR224 guarded actor, and the PR547 FIT-only archive. The separate scorer patch targets main `28cbe3b23cfcbd4365b2b7cf19f7b7ea8c0fd1bb`. These are review artifacts, not an authorized executable driver, a PR update, or a scientific result.

- `m1_evidence.py`: signed approval verification (Ed25519, separate trusted key pin, scope, expiry); fixed-batch construction through the exact FIT adapter and digest; U0→U1 counter checks; FP32 AdamW first-step and EMA tensor checks; a fresh-process read-only command for the canonical V5 continuation loader. The helper does not run the optimizer, issue authorization, or write a checkpoint. The checksum of the batch binds its tensors and keys. The proposed half-life is 22,136 presentations and both encoders exclude q. No L04 change.
- `preservation.py`: separate between-type and within-type Spearman readouts. Broad compares type means within the same donor/source/depth stratum. Fine uses frozen donor/type/source/depth strata, the same finite pairs for model and technical baseline, and a deterministic within-stratum shuffle. The shuffle is a descriptive negative control, not a calibrated null or inferential test. An absent or undefined required group cannot be averaged away. Includes a pre-transform noninterference check that compares visible intermediates byte for byte under changes to withheld values.
- `jepa-oof-stage33b-estimability-draft.patch`: separate scorer and Stage 33B changes preserving measured zero vs non-estimable and preventing selection on incomplete required target coverage. Other historical consumers are not migrated.

## Review and integration boundaries

1. The trusted launcher must pin the owner's public key out of band, verify the checkout/contract/parent on disk, and derive `verified_pins` itself. Supplying a key and its own fingerprint from an untrusted request is not authentication. No real owner key or approval is included. The #597 wrapper remains unchanged; it must not be used as the authorization boundary. Wire the new checks into one reviewed launcher, with a write-once attempt, before considering M1. Ensure all parameter names and slots are checked; per-tensor arithmetic checks alone do not prove that coverage.
2. Use the existing V5 persistence API for a child; use the read-only helper to validate canonical parent/child digests and age after persistence. A mocked readback does not demonstrate real persistence, and a single successful readback is not M2 restart equivalence.
3. For biology, freeze a permitted evaluation panel, predictors and required strata before inspecting results. Donor identity overlap checking alone does not establish fitting provenance. Do not substitute controller truth or grant access based on this draft. Apply the noninterference test upstream of fitting any statistics, with separate withheld-query and block-hidden fixtures, and include all visible outputs such as depth, thresholds, bins, token IDs, and encoder inputs. The current tests use illustrative arrays, not the production FIT producer. No scoring is an M1 acceptance criterion.
4. The remaining #594/#596 review items and V80 archive failure are outside this package.
