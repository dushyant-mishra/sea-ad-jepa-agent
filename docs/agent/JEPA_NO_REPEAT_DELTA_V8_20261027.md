### Anti-error rules for successor agents

1. **Use an exact SHA, not a current PR title or green badge**, to identify a code candidate. PR descriptions can remain stale after a reject; an old PASS stays only a past engineering event.
2. **Do not inherit the status of a parent implementation into a fixture adapter.** Same shape, digest or handler does not equal independent biological/source authority.
3. **Controller secrets and historical blind data are not target labels**. Phase2 controller truth and sealed production-synthetic families remain off-repo and firewall-bound. No view/use of local raw artifacts is permission to train.

Check `JEPA_LOCAL_ATTACHMENT_CUSTODY_RECONCILIATION_V8_20261027.csv` and older SHA ledger first.
6. **Preserve all RED**: #439, #441, #442, #443, #448, #449, #450, #452, #455. New improvements must re-run unchanged hostile suites; no converting X1/real E3 failures into permissive fixture PASS.
7. **Differing reviewer roles matter**: an author cannot accept the complete cumulative module by spawning agents or reviewing its own fixture. Incremental independent review is narrower than cumulative acceptance.

9. **Write deltas, not omnibus repeats.** Read V8, V7 and controlling specialized ledger first. Produce one additional append-only receipt for a *new verified fact*; otherwise reference existing paths.
