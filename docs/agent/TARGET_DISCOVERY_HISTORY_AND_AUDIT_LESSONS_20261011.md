## 3. Critical historical row-binding lesson

The 50K archive is stacked A then B. B resets `sample_row`. Therefore row position and sample-local row are different concepts.

Historical target-discovery explicitly required:

`global_row=np.arange(len(freeze_csv))`

before filtering/merging.

TD23 demonstrated that reset-row aliasing can generate a false positive. TD33 became the durable guard:

`PASS_GLOBAL_ROW_BINDING__RESET_INDEX_FORBIDDEN`

The first real G6 failure in October 2026 was not a new scientific ambiguity; it was an implementation that forgot this established historical interface rule.

Future audit rule: **before any real execution, enumerate every physical column dereferenced from each authenticated input and prove it exists or is prospectively derived from an explicitly frozen rule.**

## 4. Qualification failure discovered by real G6

The `fafd4309` qualification had 217 passing focused tests plus exact PR259 compatibility. That was useful but incomplete.

What it genuinely established:

- owner/runtime authority binding;
- exact PR259 physical-byte binding;
- atomic attempt marker behavior;
- G6→G7 prerequisite semantics;
- strict raw-count behavior;
- forged-NPZ semantic rejection;
- synthetic end-to-end behavior;
- G7 physical-counterpart protections.

What it did **not** establish:

- compatibility of every G6 dataframe dereference with the exact production Sample-A freeze header.

Why:

- the synthetic world physically added `global_row` because production code expected it;
- therefore tests encoded the implementation assumption rather than the real external interface.

Audit lesson:

**Synthetic fixtures must copy the external production schema, not the consumer's desired schema. Derived fields should be created by the production code under test.**

## 5. Spending-boundary lesson

The predecessor spent the immutable start marker before all metadata-only compatibility checks were complete.

Owner disposition: preserve that namespace as Attempt 0 schema qualification evidence, but allow a replacement biological/value-read opportunity after prospective repair and requalification.

## 7. Claim-boundary lessons

The project repeatedly encountered ways a technical PASS could be inflated into a scientific claim.

Keep these distinctions explicit:

- physical bytes authenticated ≠ biology validated;
- address mapping one-to-one ≠ corrected biology reproduces;
- cache successfully materialized ≠ target qualified;
- noncollapsed latent ≠ biological latent;
- low JEPA loss ≠ biological information;
- donor-membership disjointness ≠ all case rows statistically independent;
- cells/queries ≠ biological N;
- reused external evidence ≠ pristine independent validation;
- synthetic green tests ≠ real-data scientific authority.

## 8. Donor-primary inference

Donor is the biological replication unit.

Any future receipt or tournament evidence should expose exact donor identity / donor counts rather than derive biological N from repeated cell or query rows.

PR275 already found and repaired a governance bug where donor disjointness was serialized too broadly. Preserve the correction:

- unique donors = biological N;
- `independent_n_from_case_rows` should not manufacture independence;
- PASS/FAIL/NOT_ESTIMABLE remain separate.

## 9. Tournament architecture lesson

The original V1 executable scaffold materially drifted from the scientific prefreeze before real execution.

The correct response was prospective supersession, not patching the scientific meaning after looking at real corrected outcomes.

V2 therefore freezes:

- exact candidate identities;
- exact candidate gate sets;
- inheritance rules;
- C4 no-compensation rule;
- C5 specialist-only role;
- externally pinned prefreeze/evidence chain;
- false downstream authority flags;
- distinct PASS / FAIL / NOT_ESTIMABLE semantics.

Lesson: **scientific contract reconciliation must precede engineering hardening.** The project lost substantial time by hardening a V1 generation before recognizing that it no longer represented the intended science.

## 11. Safety-tooling lesson

Claude Code's local safety classifier blocked public research-data operations as PII/Auto-Mode Bypass. This was an operational restriction, not a scientific finding about the datasets.

Future response:

- do not route around denials with unrelated tools;
- report exact blocked command/classifier;
- use a reviewed script or narrow owner-granted permission;
- do not introduce unsupported claims that the public datasets are confidential simply because a safety classifier fired.

## 12. Audit checklist before any future one-shot execution

Before declaring an implementation execution-ready, independently verify:

1. exact science/spec version versus executable semantics;
2. exact branch/head and clean status;
3. physical-byte pins for all authority inputs;
4. every externally read column/key/path against the real authenticated production schema;
5. every derived field has an explicit frozen derivation rule;
6. synthetic fixtures mirror the producer schema, not consumer assumptions;
7. metadata-only failures occur before attempt-spending marker where possible;
8. actual value-read boundary is explicit;
9. receipt semantics cannot overclaim verification scope;
10. failure/NOT_ESTIMABLE/PASS remain distinct;
11. biological N is donor-primary;
12. downstream authority flags remain false unless separately authorized.

## 13. Current recovery standard

A new agent should not attempt to "clean up" contradictions by deleting old records. Preserve:

- historical positives;
- historical failures;
- withdrawn qualifications;
- failed execution namespaces;
- superseded code generations;
- exact hashes and branch heads.

The project's ability to pivot depends on knowing **why** each branch stopped, not just which branch is newest.
