# Real data, not synthetic, policy — 2026-09-09

## Rule

Synthetic fixtures are not project progress unless they expose a new concrete software defect or prevent a known regression.

## Why

The project objective is to build a framework around the frozen dataset. A fixture can prove that code rejects a malformed toy object; it cannot prove that the real population was authenticated.

## Permitted synthetic use

- malformed CSR attack;
- bad digest attack;
- duplicate logical index attack;
- wrong donor/cell attack;
- wrong projection width attack;
- pathology-read attack;
- replay corruption attack.

## Not permitted as completion evidence

- synthetic H5AD population proof;
- three-row real-asset spot check;
- fixture-only technical-completeness package;
- increasing test count without materializing real authority artifacts.

## Required completion evidence

- real 20,804-row raw-source population authority;
- replay from disk;
- real technical-completeness package;
- replay from disk;
- exact artifact hashes and package roots.
