## The contradiction, and what closed it

Before R7:

    build_pretarget_execution_authority   writes real_execution_ready False, always
    load_pretarget_execution_authority    raises unless it IS False
    canonical freeze v2 / adjudicator v2  raise unless it IS True

A package that loads could not run; a package that could run could not load. All
three canonical conclusion entrypoints sat on the unsatisfiable side, and nothing
in the frozen package ever wrote True.

The repair re-freezes the semantics in a new authority rather than editing the
frozen package, which stays read-only. The four R7 tests that pin the frozen
contradiction still pass, so it remains demonstrable rather than papered over.

## The repaired semantics

    real_execution_ready = all_required_stage1_bindings_verified
                           AND staged_authorization_present
                           AND no_forbidden_gate_opened

`True` exists only on a production execution-input authority derived from
verified Stage 1 parents plus explicit staged owner authorization. `False`
remains lawful for pre-run, test, fixture, candidate and non-execution packages,
and is refused for production canonical input.

Readiness is derived, and the API makes assignment impossible:
`materialize_production_authority` has **no** `real_execution_ready` parameter.
A caller cannot pass one. The value is computed by `derive_readiness`, and if any
conjunct raises, no package is written.

Nineteen bindings are required, each compared to a value frozen in committed
code rather than taken from the package under check — the same anti-circularity
rule R6 applied to the AT8 and age/sex parents. A package whose expectations are
its own bindings object is refused by name with
`STOP_T0_READINESS_PACKAGE_ATTESTS_TO_ITS_OWN_IDENTITY`.

Stated precisely, because the guarantee should not be overread: comparing to the
accepted values proves the package **cites** the accepted roots. It does not
prove those roots still reproduce. That is why the materializer is driven by a
live Stage 1 verification and assembles its bindings from what the replays
return. Citation and reproduction are established separately, by independent
means.

## How the canonical entrypoint consumes this — decided, with the reasoning

I was going to hand this back as a question. It is answerable from the code, so
here is the answer.

`t0_canonical_freeze_v2._freeze_target` is literally:

    a = _verified(...)                      # the external-input-authority gate
    r = freeze_target_after_role(**kwargs)  # v1's conclusion-bearing function

So v2 **is** a gate wrapper around v1's function. The V20 audit classifies
`t0_canonical_freeze_v1.freeze_target_after_role` as
`SUPERSEDED_NON_AUTHORITATIVE_PRIMITIVE` *as an entrypoint*; it remains the
implementation v2 calls.

Therefore an R7 canonical freeze that applies a stricter, satisfiable gate and
then calls that same function is architecturally identical to v2 — not a fallback
to v1. "Fallback to v1", the thing the work order forbids, means calling
`freeze_target_after_role` directly with no external-input gate, dodging the
control. Applying a stronger gate than v2's, where v2's enforces nothing because
it can never pass, is the opposite of dodging it.

I have **not** written that freeze wrapper. It belongs to Stage 2, and R7's
mandate ends at readiness. The reasoning is recorded here so Stage 2 does not
have to relitigate it, and so a reviewer can object now if they read the
boundary differently.

## Four defects found in my own R7 work

All by attacking my own code before running it, none by a failing test.

1. **An unreachable check.** `assert_production_authority_lawful` had a "records
   True but the derivation disagrees" branch. `derive_readiness` either returns
   True or raises with the failing conjunct, so there is no False to catch. Dead
   decoration of exactly the kind this lane keeps finding in its own verifiers.
   Removed, with the real discrimination — which lives in the raise — documented.

2. **A hand-written fallback that defeated the point.** The runner took the AT8
   endpoint identity from a frozen constant when the parent did not surface one.
   That would have made the endpoint self-supplied rather than verified, in a
   runner whose docstring claims the opposite. The AT8 parent loader now surfaces
   `at8_endpoint_identity` from the metadata it verified, and the runner stops
   rather than substituting.

3. **A guard that did not cover what R7 added.** The byte-semantics audit matched
   only string-literal declarations, so it classified neither R7 readiness
   module — both declare through `ACCURATE_CODE_BYTE_SEMANTICS`.

4. **The same crude-guard bug inside the fix for the crude-guard bug.** Extending
   the regex to catch constant references then flagged the contract module again,
   because a *comment* there quotes the declaration in order to explain it.

The fourth one settled the matter. Three successive text-based versions of that
check were wrong the same way, and a regex over source text cannot distinguish a
declaration from prose about a declaration. It is now parsed from the AST: only a
real dict key in a real expression counts, and comments and docstrings are not
part of the AST. Literal, constant-reference and concatenated forms are all
recognised, and tests pin each — including that a commented declaration counts
for nothing and that the module defining the constants classifies as neither.

Fixed at the level of the class rather than the instance, which is what the
earlier three patches failed to do. This is the sixth, seventh, eighth and ninth
verifier defect recorded in this lane; the pattern remains more informative than
any single instance.
