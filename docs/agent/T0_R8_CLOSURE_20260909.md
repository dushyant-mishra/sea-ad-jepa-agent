## What was broken

R7 repaired the readiness semantics for the canonical *freeze* path by building a
parallel authority module. It did not reach the *adjudication* path.
`t0_adjudicator_v2._adjudicate_from_raw_v2` calls the frozen
`verify_pretarget_execution_authority` at line 34 and
`verify_preadjudication_execution_authority` at line 48, and both require
`real_execution_ready is True` from loaders that refuse anything but `False`.

So the confirmation adjudicator was unreachable for exactly the reason the
Stage 1/2 STOP identified, and R7's repair did not apply to it. That was my miss:
I recorded all four gate lines in the STOP report and then repaired three.

## Why this is a defect, not a reading

`contract/T0_V20_EXECUTION_AUTHORITY_CONSTANTS.json` declares:

    production_requires_real_execution_ready          True
    synthetic_test_authorities_real_execution_ready   False

The contract says production requires `True`. The loader refuses `True`. R8
aligns the implementation with the contract's own constant rather than choosing
among interpretations. This is firmer ground than R7 had.

## The change, and how it is made checkable

Both loaders are re-derived from `inspect.getsource` of the frozen functions by
one textual substitution each, then exec'd into a copy of the frozen module's
globals. Every line except the substituted one is byte-identical. The module
refuses to derive unless the resulting diff has exactly four changed lines, every
one touching `real_execution_ready`. This is the method the C2 lane used to
attribute the T1 gradient defect to a single line, and it makes "only the
readiness check differs" a verifiable property rather than a claim.

The whole diff, emitted as `T0_R8_READINESS_LOADER_SOURCE_DIFF.txt`:

    -  ... or obj.get('real_execution_ready') is not False: raise ValueError('pretarget authority metadata mismatch')
    +  ... or not isinstance(obj.get('real_execution_ready'), bool): raise ValueError('pretarget authority metadata mismatch')

    -  ... or obj.get('real_execution_ready') is not False: raise ValueError('preadjudication authority metadata mismatch')
    +  ... or not isinstance(obj.get('real_execution_ready'), bool): raise ValueError('preadjudication authority metadata mismatch')

The loader now validates the field's **type**; the entrypoint decides production
readiness. That is the division of labour the contract describes — the loader
checks shape, `production_requires_real_execution_ready` is enforced where
production is claimed.

**A correction, not a loosening.** `False` is still accepted for non-production
packages. A non-boolean is still refused. And a `False` authority still fails the
production gate, which the verifier asserts explicitly rather than assuming.

The two `verify_*` functions are copied **verbatim** into the same namespace, with
a guard that refuses to copy them if they contain the readiness condition. Their
global lookup then resolves to the repaired loader. The frozen module is not
edited and nothing on it is rebound.

### Why satisfiability is shown on fixtures

Deliberate, and worth stating so it is not mistaken for a shortcut. Building a
*production* pretarget authority requires `discovery_metadata`, which carries the
AT8 column. R8 is a repair to readiness plumbing: it is not authorized to refit
discovery and has no need to re-read pathology. So the demonstration writes
authority-shaped packages through the frozen module's **own** writer, shows the
frozen loader refusing them and the repaired loader accepting them, and evaluates
the frozen adjudicator's condition against the result.

That establishes the readiness path is satisfiable, which is exactly the claim
R8 makes and no more. It does not establish that a production adjudication would
succeed; that needs the tail authority, the confirmation matrix and Stage 3.

## A defect in my own R8 work

The first version of the `verify_*` wrappers routed through the repaired loaders
by temporarily rebinding names on the frozen module and restoring them in a
`finally`. It worked and the tests passed. It was still wrong: it mutates a module
other code may hold, it is not re-entrant, and a reviewer would rightly distrust a
repair that reaches into the thing it claims not to touch.

The clean form was already available in the mechanism I had built — exec the
verifiers into the namespace that holds the derived loaders and let normal global
resolution do the work. Zero rebindings remain, confirmed by grep. Found by
reading my own code before running it, not by a failing test.
