## Item 1 — AT8 availability replayed as an explicit parent

The hardcoded `at8_availability_independently_verified` literal is gone. The
package now goes through `t0_at8_availability_authority_v1.load_availability_
authority`, which enumerates the directory, refuses a symlink or an unexpected
member, captures each member's bytes exactly once, and verifies every digest
from the captured buffers.

The decisive change is where the expected roots come from. They are frozen as
constants in the committed runner, so a reviewer reads them on the branch
independently of any directory:

    AT8_EXPECTED_PACKAGE_ROOT       3f74fa833bc1838a50d92bf3f6bdb55e6eafdb10b489fbfff142a4240466fc5a
    AT8_EXPECTED_AVAILABILITY_ROOT  e49c4e9365513d88d3afb687e452bc126dc3d39722384bc262557f84ee43523b

Reading a package's own `*_PACKAGE_ROOT_SHA256.txt` and passing it back as the
expectation is circular — the package attests to itself. Identity has to come
from outside the directory, and now does.

The replay additionally refuses an availability package that claims readiness, or
that claims it parsed, retained or emitted a magnitude. `build_authority`
receives what the replay established rather than a caller's assertion, and a
guard test fails if the literal reappears anywhere in the module, prose included.

the old fixture-based definedness test is deliberately gone: that case is
unreachable through this path, and a test asserting otherwise would have been

## A defect in my own R6 work

The preflight's covariate leak guard, as first written, serialised the whole
report to one string and substring-scanned it. That refused the report's own
`at8_availability_root_sha256` — a parent identity the report is *required* to
bind — and it fired on the first production run. It is the same crude-substring
error that earlier flagged an `age_present` header as an age value.

emitted at all: the report records the encoding's level count, its
complete-binary property and a digest instead. Both behaviours are pinned by
test, including the case that a field name containing a pathology token must be
accepted.

That is the sixth verifier defect in this lane and the third of the crude-guard
kind. The pattern is worth the reviewer's attention more than any individual
instance.
